# [SHAKEDOWN] clio — 2026-09-01 16:52

**Target:** clio (`utils/CLIO/`, skill file `utils/CLIO/INSTALL.md`)
**Target HEAD:** not a git repo *(the checkout has zero commits; everything is untracked at audit time)*
**Env:** Darwin 24.6.0 arm64 · GNU bash 3.2.57(1)-release
**Verdict:** **[path bug reproduced]** — every documented `install -m 0755 utils/CLIO/<script>.sh …`
command resolves against the current working directory, so the skill's own install steps
fail whenever it is invoked as an installed skill rather than from a repo checkout.

The audit ran against a `cp -R` sandbox copy (`INSTALL.md` copied to `SKILL.md` so the
grader could read it). The real repo was never written to, executed, or mutated.

---

## Static audit

`audit.sh --target <sandbox copy>` → exit 2 (blockers present).

### The load-bearing finding

Four install commands use a **repo-checkout-relative** script path:

| SKILL.md line | Command |
| --- | --- |
| 233 | `install -m 0755 utils/CLIO/prompt-log-to-md.sh ~/.claude/hooks/prompt-log-to-md.sh` |
| 368 | `install -m 0755 utils/CLIO/clio-codex-tail.sh ~/.claude/hooks/clio-codex-tail.sh` |
| 409 | `install -m 0755 utils/CLIO/clio-agy-tail.sh ~/.claude/hooks/clio-agy-tail.sh` |
| 472 | `bash test/clio-capture.sh` (and the three sibling harnesses) |

`INSTALL.md` mitigates this in prose — "Run once from the root of this CLIO checkout" —
which holds for the *repo* path. It does **not** hold for the *skill* path:

- `INSTALL.md` carries `name: clio` frontmatter, so Claude Code can load it as a skill.
- An installed skill lives at `~/.claude/skills/clio/` (or a project `.claude/skills/clio/`)
  with `clio-agy-tail.sh`, `clio-codex-tail.sh`, and `prompt-log-to-md.sh` as **siblings** of
  the skill file — there is no `utils/CLIO/` prefix and no `test/` directory in that layout.
- So a session that invokes the skill from any other repo runs a command whose source file
  does not exist under any CWD. That is the classic "works in the session that wrote it,
  not found in the next one" failure, in its documented form.

### False positives — recorded so they are not re-litigated

The grader flags every `~/.claude/hooks/…` and `$HOME/.claude/hooks/…` token as
"home-hardcoded — breaks when installed project-level." **Not applicable here.** Those are
not in-place invocations of bundled scripts; they are CLIO's fixed *install destination* on
the machine, which is the product's design (one shared writer at one absolute path, named by
the `settings.json` registration). They are CWD-robust by construction.

Likewise:

- `L199 )/clio-capture.sh` — this is `exec "$(dirname "$0")/clio-capture.sh"` inside the Claude
  shim: correct self-location, graded as a block by pattern only.
- `L43`/`L44`/`L206`/`L219`/`L439` "bare name — relies on PATH" — these are usage-comment and
  prose mentions, not executed commands.
- `sh, not bash` warnings — artifacts of the grader tokenizing prose and heredoc bodies. Every
  real invocation is `bash`, and the writer is explicitly written for stock macOS bash 3.2.

### Bundled-script hygiene

| Script | shebang | exec bit | self-loc |
| --- | --- | --- | --- |
| `clio-agy-tail.sh` | ok | ok | block *(false positive — see below)* |
| `clio-codex-tail.sh` | ok | ok | block *(false positive)* |
| `prompt-log-to-md.sh` | ok | ok | block *(false positive)* |

No script sources a sibling relative to itself. The single cross-script reference — the
tailers calling the shared writer — is already absolute and install-anchored:

- [`clio-codex-tail.sh:34`](utils/CLIO/clio-codex-tail.sh#L34) — `WRITER="$HOME/.claude/hooks/clio-capture.sh"`
- [`clio-agy-tail.sh:278`](utils/CLIO/clio-agy-tail.sh#L278) — `WRITER="$HOME/.claude/hooks/clio-capture.sh"`

A `BASH_SOURCE` self-location block would add nothing. **Move 2 of the standard fix is not
needed for this target — only move 1 (anchor the invocation).**

## Proposed patch

Give `INSTALL.md` a resolver at the top of the install section, then anchor the four
CWD-relative commands to it. `CLIO_SRC` resolves to the repo checkout when run from one, and
to the installed skill directory otherwise — the same command then works in both layouts.

```diff
--- a/utils/CLIO/INSTALL.md
+++ b/utils/CLIO/INSTALL.md
@@ ## Install
 ```bash
 command -v jq >/dev/null 2>&1 || { echo "jq is required. Install it: brew install jq (macOS) / apt install jq (Linux)"; return 1 2>/dev/null || exit 1; }

+# Resolve CLIO's source files whether this runs from a repo checkout or from an
+# installed skill directory (where the scripts sit beside INSTALL.md, with no
+# utils/CLIO/ prefix). Set CLIO_SRC yourself to override.
+if [ -z "${CLIO_SRC:-}" ]; then
+  for c in "$PWD/utils/CLIO" \
+           "$HOME/.claude/skills/clio" \
+           "$(git rev-parse --show-toplevel 2>/dev/null)/utils/CLIO" \
+           "$(git rev-parse --show-toplevel 2>/dev/null)/.claude/skills/clio"; do
+    [ -f "$c/prompt-log-to-md.sh" ] && { CLIO_SRC="$c"; break; }
+  done
+fi
+[ -n "${CLIO_SRC:-}" ] || { echo "CLIO source not found — set CLIO_SRC to the folder holding prompt-log-to-md.sh"; return 1 2>/dev/null || exit 1; }
+
 mkdir -p ~/.claude/hooks
@@
-install -m 0755 utils/CLIO/prompt-log-to-md.sh ~/.claude/hooks/prompt-log-to-md.sh
+install -m 0755 "$CLIO_SRC/prompt-log-to-md.sh" ~/.claude/hooks/prompt-log-to-md.sh

@@ ## Optional: Codex capture (VS Code / CLI)
-install -m 0755 utils/CLIO/clio-codex-tail.sh ~/.claude/hooks/clio-codex-tail.sh
+install -m 0755 "$CLIO_SRC/clio-codex-tail.sh" ~/.claude/hooks/clio-codex-tail.sh

@@ ## Optional: Agy capture (Antigravity CLI)
-install -m 0755 utils/CLIO/clio-agy-tail.sh ~/.claude/hooks/clio-agy-tail.sh
+install -m 0755 "$CLIO_SRC/clio-agy-tail.sh" ~/.claude/hooks/clio-agy-tail.sh
```

Two dependent notes:

1. The Codex and Agy sections are **separate copy-paste blocks** run in later shells, so each
   needs the resolver too — either repeat it, or state in prose that `CLIO_SRC` must be
   exported from the main install block. Repeating it is the safer default.
2. The test harnesses (`bash test/clio-capture.sh`) stay repo-relative on purpose: they only
   run from a checkout, and they already fail loudly if marker extraction from `INSTALL.md`
   breaks. No change recommended, but say so in the README's Tests section.

## What I could not verify

- Shakedown tests the **documented command under varied CWD and install conditions**. It does
  not instrument Claude Code's internal skill resolver, so it cannot certify how the runtime
  itself locates `utils/CLIO/INSTALL.md` when the `clio` skill is invoked — only that the
  command *as written* is not CWD-robust.
- The install block was never executed. Nothing was installed to `~/.claude/hooks`, no
  `settings.json` was touched, no launchd job was loaded. Discovery was probed with `bash -n`.
- The four test harnesses (`test/*.sh`) were read, not run, so this report makes no claim
  about whether the suite currently passes.
- The proposed `CLIO_SRC` resolver is untested as written — it is a patch proposal, not a
  verified change. Run B proves anchoring works; it does not prove this specific resolver's
  candidate list covers every install layout.

## Update — 2026-09-01, same day: patch applied

The operator accepted the patch, so the propose-don't-patch default was waived for this run.
Applied on branch `clio-path-resolution`:

- The `CLIO_SRC` resolver landed in `INSTALL.md`, repeated in the Codex and Agy sections
  because each is a separate copy-paste shell, and all three `install -m 0755` commands are
  now anchored and quoted.
- Verified by hand across five layouts: checkout root, inside `utils/CLIO/`, foreign CWD with
  an installed skill dir, no source anywhere (fails loudly with the intended message), and an
  operator-set `CLIO_SRC` override. All five behaved as designed.
- Every fenced `bash` block in `INSTALL.md` passes `bash -n`.
- The four test harnesses pass, which also confirms the heredoc markers the tests extract by
  were not disturbed.

**Separate defect found while verifying, and fixed in the same branch:** `clio-agy-tail.sh`
printed its summary line to stderr while its Codex twin used stdout, so
`test/clio-agy-tail.sh` failed on its very first assertion and none of its remaining cases
had ever run. Aligned to stdout; the harness now passes. This was pre-existing — it
reproduces on the initial commit `f4b8588` — and is not a path-resolution issue. Tracked as
FD-04 on [`FRONTDOOR.md`](../../FRONTDOOR.md).

The remaining open onboarding findings live on that board, not here.
