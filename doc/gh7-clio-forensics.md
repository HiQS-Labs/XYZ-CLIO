## Stable v1 contract
Commands: locate, search, session, journey. All successful/empty/error results use identical top-level keys: schema_version, status, operation, source, filters, records, page, journey, coverage, errors. JSON stdout, exit 0 success/empty and 2 errors. CLI help is ordinary text. Fixed row keys: record_id, timestamp, date, time, timezone, session_id, device, agent, ide, repo, repo_slug, branch, checkout, origin_id, source_event_id, prompt, references, metadata. Timestamp/date/time normalized UTC; unknown scalar metadata null (never infer IDE or human identity from agent/session). References remain source-provided array; metadata preserves extras unchanged. Source contains resolved db/helper, resolution method and candidates. Coverage always says fleet completeness unknown and capture may omit prompts; pending/fleet/note receipts surface without interpreting them as complete coverage. Errors stable code/message objects with content-free diagnostics.

Resolver precedence: explicit --db, native configured db (CLIO_CONFIG respected), existing default; otherwise shallow bounded discovery under --pulse-root or ~/git-pulse-sync (root and CLIO only, .db/.sqlite/.sqlite3 files). Validate through existing gateway, canonicalize/deduplicate paths, refuse multiple valid candidates. Broken explicit/configured paths never silently fall through. No recursive disk scan, creating DB or shell-sourcing config. Pulse is fallback discovery, not a new default storage destination. locate returns no prompt content.

Filters reuse existing query flags (repo/device/agent/session/record-id/repo-slug/origin/since/until/text/reference); whitespace-only text rejected. Search supports oldest/newest, limit 1..999 and offset >=0 with one-row lookahead via existing max1000 reader; stable timestamp+record ID order. session requires session ID and returns its chronological captured history, preserving origin identities. It does not assert a session ID alone is globally unique.

Journey requires text, fixes oldest order and offset0; matching records are the first page in chronological order. journey has fixed keys earliest_match, session_first_record, basis. Earliest match is earliest recorded keyword evidence within supplied filters. For that one match, do one additional native query scoped to origin+agent+session, oldest/limit1, with a fresh identity-only filter set (all other filters cleared) so the session's earliest captured prompt can precede the task keyword. Missing identity -> no session origin and explicit basis; no invented association. This bounded two-query operation is not a per-row N+1. Earliest session record is not proof of true session start, nor is keyword match proof the task began there. Stable tie-breaks. Empty/error keeps same shape and null journey records.
